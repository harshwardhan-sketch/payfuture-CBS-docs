# Payfuture Banking API: developer docs

Merchant-facing docs for the Payfuture Banking API: tokens (Auth API) and accounts, payouts, beneficiaries,
transactions and reports (Gateway API). Same layout as the Payfuture Cross-border Payouts docs.
Three tabs, as on the live API docs: **Integration guide** (`#/guide/...`), **Gateway API** (`#/gateway/...`) and **Auth API** (`#/auth/...`).
Plain HTML, CSS and JavaScript: no build step, nothing to install. Open `index.html` in a browser to see the site.

**Changing something? Find it in the table below, edit that file, then run `python3 tools/check.py`.**

## Where everything is

```
index.html        the page shell: header, tabs and the list of files the site loads
content/          the words on the site: edit these most often
api-spec/         the two API specs, pulled from the live API (do not edit by hand)
engine/           how the site works: menus, search, API pages (rarely edited)
styles/           colours and layout (CSS)
assets/           logo and images
tools/            spec import and the site check
```

| I want to change… | Edit |
|---|---|
| Product name, base URLs | `content/settings.js` |
| Home page and guide pages (welcome, quickstart, authentication, payouts, FAQ, …) | `content/guide.js` |
| Gateway API and Auth API tabs: menu groups and their order, page titles, the note at the top of a page, each API's Overview page | `content/api-overview.js` |
| Example requests, the error example, PKR payment detail variants | `content/examples.js` |
| Fields, descriptions, responses | Nothing here: they come from the live API. Run `python3 tools/import_spec.py` |
| A wording fix the live spec gets wrong | `FIXES` in `tools/import_spec.py`, then run it |
| Colours, spacing, fonts | `styles/base.css`, `styles/site.css` |

## Files

`content/`
- `content/settings.js`: product name and base URLs. Loaded first
- `content/guide.js`: home page and the Integration guide
- `content/api-overview.js`: API menu, titles, notes, Overview page
- `content/examples.js`: example requests and values

`api-spec/`
- `api-spec/auth.js`, `api-spec/gateway.js`: generated by `tools/import_spec.py` from the live specs

`engine/`
- `engine/app.js`: router, menus, shared helpers
- `engine/api-pages.js`: every API page (parameters + code panel), built from the specs
- `engine/search.js`: site search (header button, Ctrl/⌘K, "/")
- `engine/motion.js`: small animations; `engine/boot.js`: first render

`tools/`
- `tools/import_spec.py`: pulls the two live specs into `api-spec/`
- `tools/check.py`: opens every page in headless Chrome, checks links and banned words

## When the API changes
1. `python3 tools/import_spec.py` (pulls both specs from the live API).
2. A new endpoint appears in its tag's menu group automatically. To place it in a curated group or give it a title, edit `content/api-overview.js`.
3. `python3 tools/check.py`, fix what it reports, then commit.

## Content rules
- The live API spec and Payfuture's internal records are the only sources.
- No internal names, provider names, merchant names, secrets or credentials.
- No "dummy" values: give realistic examples.
- The site loads nothing from other websites (only Google Fonts, with a fallback).
